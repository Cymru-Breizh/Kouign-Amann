# Kouign-Amann

An evaluation suite for testing large language model (LLM) capabilities in Welsh and Breton. Built on [DeepEval](https://deepeval.com/) with [LiteLLM](https://docs.litellm.ai/) for model-agnostic provider support (OpenAI, Anthropic, Ollama, etc.).

# Getting Started

## 1. Setting up an Ollama server (for open models)

See `infra/ollama/README.md` for full instructions. In short:

```bash
# On your Linux server with a GPU:
cd infra/ollama
make up           # Start Ollama
make pull         # Download llama3 (8B) + llama3.2:1b
make test         # Quick test
```

## 2. Testing the pipeline with llama3

Ensure `openai.env` contains:

```
OLLAMA_API_BASE=http://ollama:11434
```

Build the Docker image and run a small test to verify everything works:

```bash
make eval MODEL=ollama/llama3 EVAL=welsh-mmlu-aligned-public-public MAX_SAMPLES=10
```

If that works, run a full eval:

```bash
make eval MODEL=ollama/llama3 EVAL=welsh-mmlu-aligned-public-public
```

Or all evals at once:

```bash
make eval MODEL=ollama/llama3
```

## 3. Using other models

```bash
# OpenAI (requires OPENAI_API_KEY in openai.env)
make eval MODEL=gpt-4o EVAL=welsh-mmlu-aligned-public

# Anthropic (requires ANTHROPIC_API_KEY in openai.env)
make eval MODEL=anthropic/claude-sonnet-4-20250514 EVAL=welsh-mmlu-aligned-public

# Local HuggingFace server (see infra/hf-server)
# hf/auto auto-detects which model the server is serving
make eval MODEL=hf/auto EVAL=brythonic-translation-cy-en-public

# Run a single translation direction with limited samples
make eval MODEL=gpt-4o EVAL=brythonic-translation-br-cy-public MAX_SAMPLES=50
```

## Evaluation mode

Models are evaluated **without reasoning / thinking enabled**. For Ollama models, the runner passes `think=False` so reasoning models (e.g. `gemma4:26b`, `qwen3`) emit answers directly rather than spending output tokens on internal chain-of-thought. This keeps results comparable across reasoning and non-reasoning models, and avoids the failure mode where short `max_tokens` budgets (e.g. 10 for MCQ) get fully consumed by hidden reasoning, leaving an empty answer.

## Available evals

### Welsh MMLU-aligned (multiple-choice)

Human-reviewed Welsh translations of Global-MMLU high-school questions. Scored by accuracy (exact match on A/B/C/D).

| Eval | Samples | Description |
|------|---------|-------------|
| `welsh-mmlu-aligned-public` | ~50% | Public split (Welsh) |
| `welsh-mmlu-aligned-private` | ~50% | Private split (Welsh) |
| `welsh-mmlu-aligned-en-public` | ~50% | Public split (English parallel) |
| `welsh-mmlu-aligned-en-private` | ~50% | Private split (English parallel) |

The English parallel evals use the same questions and answer keys as the Welsh versions, serving as a high-resource baseline for comparison.

Splits are stratified by subject.

### Brythonic translation (BLEU)

Human-reviewed translations from the ARBRES-Kenstur dataset — 1,443 quad-lingual sentences (Breton, French, English, Welsh). Scored by corpus BLEU.

Each direction has public and private splits (e.g. `brythonic-translation-br-cy-public`, `brythonic-translation-br-cy-private`).

| Direction | Eval name prefix |
|-----------|-----------------|
| Breton → Welsh | `brythonic-translation-br-cy` |
| French → Welsh | `brythonic-translation-fr-cy` |
| Breton → English | `brythonic-translation-br-en` |
| Welsh → Breton | `brythonic-translation-cy-br` |
| Welsh → French | `brythonic-translation-cy-fr` |
| Welsh → English | `brythonic-translation-cy-en` |
| English → French | `brythonic-translation-en-fr` |
| French → English | `brythonic-translation-fr-en` |

The EN↔FR directions serve as high-resource baselines for comparison.

Append `-public` or `-private` to any eval name above to run only that split.

### Welsh LLM texts (classification)

Given two Welsh texts on a cultural topic — one generated by an LLM, the other human-corrected — the model must identify which is the human-corrected version. Scored by accuracy (exact match on A/B).

| Eval | Samples | Description |
|------|---------|-------------|
| `welsh-llm-texts-public` | ~50% | Public split |
| `welsh-llm-texts-private` | ~50% | Private split |

## Public / private splits

Each eval is split into public and private subsets for contamination detection. Public JSONL files live in `evals/` and are committed to this repository. Private JSONL files live in `evals-private/`, which is a git submodule pointing to a separate private repository (`Cymru-Breizh/Kouign-Amann-private`).

To set up the private submodule after cloning:

```bash
git submodule update --init
```

If you don't have access to the private repository, the public evals will still work — private evals will simply be unavailable. The eval runner (`run_all.py`) checks `evals-private/` first for any `_private` JSONL file, falling back to `evals/`.

The `create_eval.py` scripts write public files to `evals/` and private files to `evals-private/` automatically.

### Changing submodule remotes

If you fork the private repositories or host them elsewhere, you can point the submodules at different URLs without modifying any code. The two submodules are:

| Submodule | Path | Default remote |
|-----------|------|---------------|
| Private evals | `evals-private/` | `Cymru-Breizh/Kouign-Amann-private` |
| Source scripts | `src/` | `Cymru-Breizh/Kouign-Amann-src` |

To change a submodule's remote URL:

```bash
# Update .gitmodules and the local config in one step
git submodule set-url evals-private git@github.com:YourOrg/your-private-evals.git
git submodule set-url src git@github.com:YourOrg/your-src-repo.git

# Re-sync and pull from the new remote
git submodule sync
git submodule update --init --remote

# Commit the updated .gitmodules
git add .gitmodules
git commit -m "Point submodules at new remotes"
```

The rest of the codebase references `evals-private/` and `src/` by path only, so no other files need changing.

## Creating new evals

The `src/` directory is a private git submodule (`Cymru-Breizh/Kouign-Amann-src`) containing the `create_eval.py` scripts and source data for each eval. It is private because the scripts contain splitting logic (seeds, stratification) that would allow reconstruction of the private evaluation splits.

### Step 1: Write a `create_eval.py` script

Create `src/{eval-name}/create_eval.py` that reads your source data and writes JSONL files. Each line must follow this format:

```json
{"input": [{"role":"system","content":"..."}, {"role":"user","content":"..."}], "ideal": "expected_answer", "sample_id": "unique-id"}
```

The script should split samples into public and private (50/50 with a fixed seed for reproducibility) and write them to:
- `evals/{eval-name}/data/{eval-name}/samples_public.jsonl`
- `evals-private/{eval-name}/data/{eval-name}/samples_private.jsonl`

Here is a minimal example:

```python
#!/usr/bin/env python3
import json
import random
from pathlib import Path

HERE = Path(__file__).resolve().parent
PUBLIC_DIR = HERE.parents[1] / "evals" / "my-eval" / "data" / "my-eval"
PRIVATE_DIR = HERE.parents[1] / "evals-private" / "my-eval" / "data" / "my-eval"

SYSTEM_MESSAGE = "You are answering questions about Welsh. Reply with a single letter: A, B, C, or D."

def create():
    # Load and process your source data here
    samples = []
    for i, item in enumerate(your_data):
        samples.append({
            "input": [
                {"role": "system", "content": SYSTEM_MESSAGE},
                {"role": "user", "content": item["question"]},
            ],
            "ideal": item["answer"],
            "sample_id": f"my-eval-{i:04d}",
        })

    # 50/50 public/private split with fixed seed
    rng = random.Random(42)
    indices = list(range(len(samples)))
    rng.shuffle(indices)
    n_public = len(samples) // 2
    public = [samples[i] for i in indices[:n_public]]
    private = [samples[i] for i in indices[n_public:]]

    # Write JSONL
    for path, rows in [(PUBLIC_DIR / "samples_public.jsonl", public),
                        (PRIVATE_DIR / "samples_private.jsonl", private)]:
        path.parent.mkdir(parents=True, exist_ok=True)
        with open(path, "w", encoding="utf-8") as f:
            for s in rows:
                f.write(json.dumps(s, ensure_ascii=False) + "\n")

if __name__ == "__main__":
    create()
```

Run it inside the Docker container:

```bash
make create
# Inside the container:
cd /app/src/{eval-name}/
python3 create_eval.py
```

### Step 2: Register the eval in `run_all.py`

Add entries for both splits to the `EVALS` dict in `deepeval_evals/run_all.py`:

```python
EVALS = {
    # ...existing evals...
    "my-eval-public": {
        "jsonl": "my-eval/data/my-eval/samples_public.jsonl",
        "metric": "mcq",       # see available metrics below
        "max_tokens": 10,
    },
    "my-eval-private": {
        "jsonl": "my-eval/data/my-eval/samples_private.jsonl",
        "metric": "mcq",
        "max_tokens": 10,
    },
}
```

Available metrics:
- **`mcq`** — Multiple-choice accuracy. Extracts the first A/B/C/D letter from the response and compares to `ideal`. Use `max_tokens: 10`.
- **`exact_match`** — Case-insensitive string match (after stripping punctuation). Good for short answers like Yes/No.
- **`bleu`** — Corpus-level SacreBLEU score. Use for translation evals. Set `max_tokens: 500` or higher.

### Step 3: Add a test file (optional)

Create `deepeval_evals/tests/test_{eval_name}.py` for pytest integration. See existing test files for the pattern.

## Local infrastructure (`infra/`)

The `infra/` folder contains Docker configurations for running local inference servers on a Linux server with a GPU.

### `infra/ollama/` — Ollama Server

Run open models (llama3, mistral, gemma2, etc.) via [Ollama](https://ollama.com/) with GPU acceleration.

```bash
cd infra/ollama
make up           # Start the server
make pull         # Download llama3 (8B) + llama3.2:1b
make gpu-check    # Verify GPU is available
make test         # Quick test
make down         # Stop the server
```

Set `OLLAMA_API_BASE=http://YOUR_SERVER_IP:11434` in `openai.env`, then:

```bash
make eval MODEL=ollama/llama3 EVAL=welsh-mmlu-aligned-public
```

See [infra/ollama/README.md](infra/ollama/README.md) for full instructions (including NVIDIA Container Toolkit setup).

### `infra/hf-server/` — HuggingFace Server

A lightweight inference server compatible with the OpenAI API (`/v1/chat/completions`), loading any HuggingFace model via `transformers`. Useful for testing fine-tuned models not available through Ollama.

```bash
cd infra/hf-server
# Create an hf.env file with your HuggingFace token:
echo "HF_TOKEN=hf_..." > hf.env
# Change MODEL_ID in docker-compose.yml if needed
docker compose up -d
```

The server listens on port 8000. To run evals against it:

```bash
make eval MODEL=hf/auto EVAL=welsh-mmlu-aligned-public
```

`hf/auto` auto-detects which model the server is serving.
